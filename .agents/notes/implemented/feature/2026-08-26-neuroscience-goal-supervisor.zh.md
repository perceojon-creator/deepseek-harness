# Agent Note: 目标监督器完成审查

Status: implemented

[English](2026-08-26-neuroscience-goal-supervisor.md) | 中文

## 问题

目标工具接受模型对活动目标发出的完成请求。模型可能只报告进度而没有运行有意义的检查，因此完成审查需要记录的工具结果和独立评估器的决定。

## 决策

`@deepseek-ai/dsh-goal-supervisor` 结合模型指示、事件启发式检测、LLM 评估器、情景摘要和面向模型的完成检查。模块名中的神经科学术语仅作为灵感来源：每一层都是提示词、正则或事件模式启发式检查，或一次模型调用。

1. **自审和进度账本：** `supervisor:self-audit` 和准入轮次的账本消息会要求模型汇报子任务及证据。这些只是提示词指示；包不会解析或强制执行所要求的区块。
2. **事件启发式检测：** `detectEvasion`、`PerseverationTracker`、`IntentionTracker` 和 `analyzeReasoningQuality` 会检查当前轮次的推理文本、工具参数及配对的工具结果。验证检测会识别运行已知测试、构建、类型检查或 lint 程序的 `bash` 和 `pwsh` 命令；每个已识别的验证调用的结果都必须不是错误，且不以失败的退出码、信号或超时标记结尾。意图漂移匹配第一人称承诺措辞，并忽略在其自身分句中被否定的承诺；含糊措辞检查只统计措辞。这些检查无法判断命令是否充分测试目标。
3. **监督器评估：** 对每个活动目标，`agent/turn-stopping` 都会评估当前轮次；当每个已记录的代码修改之后都有成功的验证时，`tools/pre-execute` 也会评估完成请求。评估器会收到配置字符数限制内记录的工具调用、结果文本和 assistant 推理。`goal-supervisor/llm-request` 和 `goal-supervisor/llm-result` 会记录完整的辅助请求和响应，但不会将它们加入派生对话历史。如果配置的提供方和模型均有效，就使用它们；否则使用当前 Agent 的提供方和模型。评估失败、超时、被取消或无法解析时结果为 `abstain`，绝不会是 `redirect`。每个请求都携带调用方轮次或工具调用的信号，并与 `supervisorTimeoutMs` 超时合并。
4. **情景巩固：** 管理器会将上一份摘要与上次成功巩固以来的活动合并。摘要保存在进程内存中，因此跨上下文压缩保留；进程重启后，会在下一个配置的间隔从会话事件重建。
5. **完成检查：** `tools/pre-execute` 会检查活动目标 ID 和修订号，要求该轮次有成功且可识别的验证，并要求评估器审查请求，之后才允许面向模型的 `update_goal(complete)`。`redirect` 会拒绝请求；`abstain` 会在记录警告后允许请求（失败时放行），因为确定性的验证要求已经满足，除非该调用已被取消。批准不会被缓存，因此不会延续到其他轮次或修订号。此检查不会拦截直接调用目标服务的代码。
6. **有上限的 steering：** 轮次停止时，监督器会在 `redirect`，或该轮次调用了配置的代码修改工具或尝试完成目标却没有成功验证时进行 steering（中途引导）。两者都未发生的轮次（例如调研或文档轮次）不会因缺少验证而被引导。同一目标修订号的每个轮次最多引导 `maxConsecutiveRedirects` 次（默认 3 次）；用尽后监督器记录警告、跳过评估器并允许轮次结束，之后的轮次数由目标轮次上限约束。
7. **限定范围的状态：** 提示词段落为组装上下文中的 Agent 渲染。显著性、巩固和引导预算状态按 Agent 存储，并绑定到一个目标 ID 和修订号；批准完成会清除显著性，Agent 销毁会丢弃全部状态。

## 测试

单元测试覆盖各项启发式检查、裁决解析和巩固重试。组合测试会将插件与目标、工具和系统提示词服务一同加载，并通过其监听器驱动多个轮次：被拒绝的完成请求使 `goal.phase` 保持活跃，引导预算在 N 次引导后停止，评估器失败和无法解析的输出不会触发引导，超时的请求会被中止，连续三个轮次中重复的非零 `bash` 退出会产生 `PERSEVERATION`，被否定的承诺不会产生 `INTENTION_DRIFT`，redirect 给出的显著性会出现在下一轮的账本中。

## 考虑过的替代方案

- **独立的执行者与审查者 Agent**——拒绝，因为这会拆分当前会话上下文并增加模型调用。
- **将批评作为合成用户消息注入**——拒绝，因为外部消息会改变对话，而不是限制完成工具。
- **将命令输出视为语义正确性的证明**——拒绝，因为进程成功退出并不能证明检查覆盖了目标。

## 后果

- 通过面向模型的目标工具完成目标，需要在最后一次已记录的代码修改之后有成功且可识别的验证（未修改代码时无需验证），且评估器未对该请求返回 `redirect`。
- 提示词指示和命令识别仍是启发式；二者都不能保证语义完整性。
- 有活动目标时，每次轮次停止都会调用评估器（直到引导预算耗尽），并增加一次受 `supervisorTimeoutMs` 约束的 LLM 往返延迟。
- 评估器不可用时不会阻止已验证的完成请求。
- 情景摘要仅保存在进程内存中，进程重启后会从持久会话事件重建。

## 已知限制与延期工作

- 跨代码库验证命令和目标专用验证仍由上层应用负责。
- 完成检查覆盖 `update_goal` 工具执行，不覆盖直接调用目标服务的代码。
